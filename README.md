# MAGverify

MAGverify assesses the integrity of metagenome assemblies and metagenome-assembled genomes (MAGs) using PacBio HiFi reads. Its ten modules cover read mapping, circularity, clipping, false closure, phantom sequences, repeats, taxonomic chimeras, false duplication, assembly variants and integrated QC.

## 1. Installation

MAGverify supports Linux with Conda or Mamba. Create the environment from the repository root:

```bash
git clone https://github.com/songmj86/MAGverify.git
cd MAGverify
mamba env create -f environment.yml
conda activate MAGverify
MAGverify doctor
MAGverify list
```

The environment includes anvi'o v9 and the command-line tools used by MAGverify. `MAGverify doctor` checks executable availability; it is not a full pipeline test. Detailed installation and environment verification are described in [Installation](docs/INSTALL.md). See [Recorded tool versions](docs/TOOL_VERSIONS.md) for software versions.

## 2. Input preparation

Run these steps once before the analysis modules.

| Step | Command | Used by |
| --- | --- | --- |
| GTDB R232 MMseqs2 database | `MAGverify prep-chimera --gtdb-dir DIR -o DB_DIR -t N` | `chimera --database` |
| MAG taxonomy table | `prep_gtdbtk_summary_to_mag_taxonomy.py --gtdbtk-dir DIR -g DIR -o DB_DIR` | `chimera --mag-taxonomy` |
| Single-copy gene annotation (anvi'o) | `MAGverify prep-scg -a DIR -o OUTPUT -t N` | `false-closure`, `chimera` |
| Assembler circularity table | `MAGverify prep-circularity -c FILE [-c FILE ...] -g DIR -o OUTPUT` | `circularity` (optional), `false-closure` |

`prep-scg` and `prep-circularity` use the same `-o` as the analysis modules, so their outputs are found automatically. The MMseqs2 database uses three files from **GTDB R232**:

| Download | Content |
| --- | --- |
| [`gtdb_proteins_aa_reps_r232.tar.gz`](https://data.gtdb.ecogenomic.org/releases/release232/232.0/genomic_files_reps/gtdb_proteins_aa_reps_r232.tar.gz) | Predicted amino-acid sequences from GTDB representative genomes (~123 GB compressed) |
| [`bac120_taxonomy_r232.tsv`](https://data.gtdb.ecogenomic.org/releases/release232/232.0/bac120_taxonomy_r232.tsv) | Bacterial genome accession → full GTDB lineage |
| [`ar53_taxonomy_r232.tsv`](https://data.gtdb.ecogenomic.org/releases/release232/232.0/ar53_taxonomy_r232.tsv) | Archaeal genome accession → full GTDB lineage |

Download commands, database construction, the MAG taxonomy format and SCG annotation are described in [Input preparation](docs/INPUT_PREPARATION.md).

## 3. Run the analysis modules

Run each command separately in the following order, using the **same `-o`** throughout. The examples use 100 threads; adjust this to the CPU allocation. The mapping manifest created in Step 1 is reused automatically by later modules. No `00_config.sh` or separate gene-taxonomy module is needed; complete [Input preparation](#2-input-preparation) first. Detailed module prerequisites and outputs are described in [Module inputs and outputs](docs/MODULES.md).

Read mapping (`map`, `circularity`) and anvi'o profiling (`variants`) process one assembler at a time with all `-t` threads, because these steps already use many threads and much memory. In `map`, the alignment-class BAMs of one assembler are built while the next assembler is mapped. `clipping`, `phantom` and `false-duplication` process assemblers in parallel and divide `-t` between them; set `PARALLEL_JOBS=N` before the command to run fewer at once. Use `-m N` (GB) with `map`, `circularity`, `repeats` or `variants` to keep memory within a limit.



## Input data

- **Assemblies** — A input folder of assembly FASTA files generated by multiple assemblers (.fa, .fasta or .fna), specified using `-a`. Contig IDs must be unique across assembly files.
- **MAGs** — A input folder of MAG FASTA files (one file per MAG), specified using `-g`. MAG contig IDs must match those in the original assembly files.
- **Reads** — A input folder of PacBio HiFi read files (.fastq, .fq, .fastq.gz or .fq.gz), specified using `-r` for read mapping. Several files are joined once into `00_prep/hifi_reads.fastq[.gz]`. The mapping manifest records the reads, so later modules reuse them without `-r`.
- **Output** — An output folder specified using `-o`. Use the same folder across all modules to reuse completed results.

Detailed input specifications are described in [Input formats](docs/INPUT_FORMATS.md).





### 1. Read mapping

```bash
MAGverify map \
  -a /path/to/assemblies \
  -r /path/to/hifi_reads \
  -o /path/to/MAGverify_output \
  -t 100
```

Maps PacBio HiFi reads separately to each original assembler FASTA, generating alignment evidence for downstream integrity assessments. The module writes the mapping manifest `01_mapping/mapping_manifest.tsv` (also linked as `results/mapping_manifest.tsv`), which lists each assembler FASTA, its HiFi BAM and the read file; later modules locate the BAMs and reads through this file.

### 2. Circularity

```bash
MAGverify circularity \
  -a /path/to/assemblies \
  -g /path/to/MAGs \
  -o /path/to/MAGverify_output \
  -t 100
```

Evaluates read support for circular junctions to assess whether assembled contigs are circular. The assembler circularity table from `prep-circularity` is optional. Without it, `Circular` is the read-supported call. With the assembler-reported circularity per MAG, `Circular` is Y only when the assembler and the reads agree (`High_confidence_circular`), and MAGs the reads support but the assembler did not call circular are listed as `Additional_circular_candidate`.

### 3. Clipping

```bash
MAGverify clipping \
  -a /path/to/assemblies \
  -g /path/to/MAGs \
  -o /path/to/MAGverify_output \
  -t 100
```

Detects clipping events and evaluates their support from HiFi read alignments. This and later modules reuse Step 1 mapping from the same output directory. If no mapping exists, supply `-r` alongside the assemblies so mapping can be prepared.

### 4. False closure

```bash
MAGverify false-closure \
  -a /path/to/assemblies \
  -g /path/to/MAGs \
  -o /path/to/MAGverify_output \
  -t 100
```

Identifies potential false circular closures by evaluating assembler circularity calls against read and clipping evidence. Requires `MAGverify prep-scg` and `MAGverify prep-circularity` with the same `-o`; another assembler circularity table can be given with `--assembler-circularity TSV`.

### 5. Phantom sequences

```bash
MAGverify phantom \
  -a /path/to/assemblies \
  -g /path/to/MAGs \
  -o /path/to/MAGverify_output \
  -t 100
```

Screens assembled sequences for regions lacking support from HiFi read coverage and raw-read k-mers.

### 6. Repeats

```bash
MAGverify repeats \
  -a /path/to/assemblies \
  -g /path/to/MAGs \
  -o /path/to/MAGverify_output \
  -t 100
```

Identifies repetitive sequence regions and quantifies their extent across contigs and MAGs. Repeat detection and false-duplication testing are separate assessments.

### 7. Taxonomic chimera

```bash
MAGverify chimera \
  -a /path/to/assemblies \
  -g /path/to/MAGs \
  --database /path/to/MAGverify_db/GTDB_R232 \
  --mag-taxonomy /path/to/MAGverify_db/MAG_taxonomy.tsv \
  -o /path/to/MAGverify_output \
  -t 100
```

Screens for taxonomically inconsistent assembled sequences using gene-level taxonomy and HiFi read evidence. `/path/to/MAGverify_db` is the database directory from [Input preparation](docs/INPUT_PREPARATION.md). Alternatively, replace `--database PREFIX` with `--taxonomy /path/to/gene_taxonomy.tsv` when a compatible gene taxonomy table already exists. `--mag-taxonomy` is a separate MAG-level classification input. Gene taxonomy is computed within this module; SCG annotation comes from `MAGverify prep-scg`. Chimera assessment also uses validated clipping results.

### 8. False duplication

```bash
MAGverify false-duplication \
  -a /path/to/assemblies \
  -g /path/to/MAGs \
  -o /path/to/MAGverify_output \
  -t 100
```

Evaluates candidate false duplications using HiFi read mapping and clipping evidence.

### 9. Assembly variants

```bash
MAGverify variants \
  -a /path/to/assemblies \
  -g /path/to/MAGs \
  -o /path/to/MAGverify_output \
  -t 100
```

Identifies assembly variants and evaluates read-level support for alternative alleles. This step may need substantial RAM; set `-m N` (GB) when appropriate.

### 10. Integrated QC summary

```bash
MAGverify summary \
  -a /path/to/assemblies \
  -g /path/to/MAGs \
  -o /path/to/MAGverify_output \
  -t 100
```

Integrates results from completed modules into a genome integrity summary and validates MAG IDs, contig memberships, counts and table consistency. Validation failures return a nonzero exit status. For a partial run, use `--include clipping,chimera` (or the modules completed). The summary does not rerun analysis modules.

## 4. Results

Final tables are linked under `OUTPUT_DIR/results/`; module directories retain the intermediate files.

| Module | Main output files |
| --- | --- |
| Read mapping | `mapping_manifest.tsv` |
| Circularity | `circularity_mag.tsv` |
| Clipping | `clipping_sites.tsv`, `clipping_contig.tsv`, `clipping_mag.tsv` |
| False closure | `false_closure_contig.tsv`, `false_closure_mag.tsv` |
| Phantom sequences | `phantom_contig.tsv`, `phantom_mag.tsv` |
| Repeats | `repeats_contig.tsv`, `repeats_mag.tsv` |
| Taxonomic chimera | `chimera_contig.tsv`, `chimera_mag.tsv` (plus gene taxonomy outputs) |
| False duplication | `false_duplication_contig.tsv`, `false_duplication_mag.tsv` |
| Assembly variants | `variants_contig.tsv`, `variants_mag.tsv` |
| Integrated QC summary | `summary_contig.tsv`, `summary_mag.tsv` |

Keep the results directory and its module subdirectories together so the symbolic links remain valid.
